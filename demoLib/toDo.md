# Список задач по рефакторингу фронтенд-модулей Демо-объектов (demoLib)

1. **Стандартизация экспорта классов (`ES-modules`)**
   - **Описание:** В текущей реализации `DemoA.js` использует именованный экспорт (`export class DemoA`), а наследующие классы (`DemoRastr2d.js`, `DemoVideo.js`) используют анонимный экспорт по умолчанию (`export default class extends DemoA`).
   - **Задача:** Привести все модули в `demoLib/` к единому стандарту именованного или именованного+default экспорта (например, `export class DemoRastr2d extends DemoA`).

2. **Изоляция DOM-элементов и предотвращение конфликтов `id`**
   - **Описание:** В методах `render()` и `renderTools()` контейнеры и canvas создаются с фиксированными значениями атрибута `id` (`#demoDIV`, `#canvas`, `#toolsDIV`). Это делает невозможность одновременного монтирования нескольких Демо-объектов в одном DOM-дереве.
   - **Задача:** Перейти на использование уникальных идентификаторов (генерация UUID/префиксов экземпляра) или обращение напрямую к сохраненным ссылкам на DOM-элементы без жесткой привязки к `id`.
