# Архитектура проекта ЛЕММА (ЛЕкционная МультиМедиа Аудитория)

## 1. Общие принципы и структура проекта
Проект построен по принципу **Толстого клиента** и **Вырожденного сервера приложений**. 
*   **Вырожденный сервер:** Не содержит прикладной (бизнес) логики. Его единственная задача — технический транзит данных от клиентского JS-приложения к СУБД MySQL и обратно.
*   **Бизнес-логика:** Полностью сосредоточена на стороне клиента (в браузере) и частично в виде SQL-скриптов/процедур на стороне СУБД.
*   **Локальность:** Все сторонние библиотеки и комплекты скриптов размещаются исключительно локально внутри проекта. Использование внешних CDN запрещено.

## 2. Архитектура слоя данных (Работа с СУБД)
Проект работает с несколькими изолированными базами данных, каждая из которых имеет свою схему.

### Структура директорий базы данных:
*   Все SQL-скрипты для работы с базами данных хранятся в корневой папке `dbLib/`.
*   Каждая БД имеет свою изолированную поддиректорию.
*   Библиотека для СУБД ММ-Лекций располагается строго в папке: `dbLib/dbMML/`.

### JS-модули API (Интерфейс к базам данных):
*   Каждой базе данных соответствует свой JavaScript-модуль, выступающий в роли API.
*   Для базы данных ММ-Лекций этот модуль называется **`dbMML.js`**.
*   **Внутреннее устройство модуля:** Максимально простое. Для каждого физического SQL-скрипта из папки `dbLib/dbMML/` внутри модуля `dbMML.js` создается собственная одноименная функция, которая этот скрипт вызывает и возвращает результат.

### Стандарты именования и работы со скриптами (Паттерн JSON-обмена):
Для каждой основной сущности (например, `Card`, `Slide`, `Section`) реализуется строгий набор скриптов и соответствующих им JS-функций:

1.  **Создание: `New<Сущность>(_...)`** — принимает на вход только обязательные параметры (`NOT NULL` поля) для инициализации объекта. Возвращает созданный экземпляр в виде **легковесного JSON-объекта** (включая сгенерированный `ID`).
2.  **Чтение и Обновление: `Get<Сущность>(ID)` / `Set<Сущность>(Object)`** — функции чтения и модификации данных. Они работают исключительно с **легковесными JSON-объектами** сущностей.

### Правило изоляции тяжелых полей (LONGBLOB):
*   Значения «тяжелых полей» (`Demo`, `Video`) **категорически запрещено** включать в состав основных JSON-объектов сущностей при вызовах `New*`, `Get*` или `Set*`.
*   Для работы с бинарными данными создаются строго изолированные, отдельные целевые скрипты и функции чтения/записи, оперирующие только по `ID`.
    *   *Примеры:* `GetDemo(Card_ID)`, `SetDemo(Card_ID, Blob)`, `GetVideo(Section_ID)`, `SetVideo(Section_ID, Blob)`.

### Стандарты именования и работы со скриптами (Паттерн JSON-обмена):
Для каждой основной сущности (например, `Card`, `Slide`, `Section`) реализуется строгий набор скриптов и соответствующих им JS-функций:

1.  **Создание: `New<Сущность>(_...)`** — принимает на вход только обязательные параметры (`NOT NULL` поля) для инициализации объекта. Возвращает созданный экземпляр в виде **легковесного JSON-объекта** (включая сгенерированный `ID`).
2.  **Чтение и Обновление: `Get<Сущность>(ID)` / `Set<Сущность>(Object)`** — функции чтения и модификации данных. Они работают исключительно с **легковесными JSON-объектами** сущностей.

### Правило изоляции тяжелых полей (LONGBLOB):
*   Значения «тяжелых полей» (`Demo`, `Video`) **категорически запрещено** включать в состав основных JSON-объектов сущностей при вызовах `New*`, `Get*` или `Set*`.
*   Для работы с бинарными данными создаются строго изолированные, отдельные целевые скрипты и функции чтения/записи, оперирующие только по `ID`.
    *   *Примеры:* `GetDemo(Card_ID)`, `SetDemo(Card_ID, Blob)`, `GetVideo(Section_ID)`, `SetVideo(Section_ID, Blob)`.

### Механизм подключения к БД (Сессии и безопасность):
Транзит данных от клиентского JS API к MySQL защищен механизмом сессионного подключения через вырожденный PHP-сервер.:

1.  **Первичное подключение (`connectDB_MML.php`):**
    *   Вызывается из JS API при старте сессии.
    *   Принимает параметры подключения (на основе `settings_MML.php`).
    *   Проверяет успешность соединения с MySQL.
    *   В случае успеха **скрывает (сохраняет) параметры подключения в глобальном массиве `$_SESSION`** на стороне сервера, чтобы не передавать их по сети повторно и не хранить в открытом виде.
2.  **Повторное подключение в рамках сессии (`reconnectDB_MML.php`):**
    *   Каждый новый изолированный PHP-скрипт (вызываемый функциями из `dbMML.js`) в рамках текущей сессии выполняет подключение к БД исключительно через инклюд/вызов скрипта `reconnectDB_MML.php`.
    *   Этот скрипт автоматически извлекает параметры авторизации из `$_SESSION` и восстанавливает активное соединение с базой данных `demotest`.

## 3. Требования к коду и документированию (Style Guide для ИИ)
При генерации и изменении кода агент должен строго соблюдать следующие правила:

### Легковесный и человеко-читаемый код (YAGNI / KISS):
*   Используйте чистый, нативный JavaScript (**Vanilla JS**), без тяжелых фреймворков и лишних абстракций.
*   Код должен быть простым и прямолинейным, чтобы его мог легко читать и поддерживать человек. Избегайте «умных» однострочников и запутанных синтаксических конструкций.

### Человеко-ориентированные комментарии:
*   Каждая функция в `dbMML.js` и клиентских модулях должна быть снабжена понятным комментарием на русском языке.
*   Комментарий должен объяснять **бизнес-смысл** операции (зачем это делается), а не просто пересказывать код техническими терминами.
*   Обязательно документируйте назначение параметров функции и структуру возвращаемого объекта.

## 4. Специфика работы с медиаданными (LONGBLOB)
*   Сущности проекта содержат тяжелые бинарные поля: `Demo` (демонстрации) и `Video` (запись лектора).
*   Передача этих данных между MySQL, вырожденным сервером и клиентом должна происходить максимально эффективно, без блокирования основного потока приложения и избыточного перерасхода оперативной памяти.

## 5. Архитектура библиотек Демо-объектов (Клиентская часть)
Для поддержки динамических и интерактивных демонстраций (карт, 3D-объектов, управления видеопотоком) на фронтенде создается изолированная экосистема модулей.

### Структура директорий:
*   Все программные компоненты Демо-объектов хранятся в корневой клиентской папке `demoLib/`.

### Компоненты и наследование:
1.  **Базовый модуль `DemoA.js`:**
    *   Содержит методы **«абстрактного класса»** Демо-объекта (базовый интерфейс).
    *   Задает единый жизненный цикл и общие методы для всех типов демонстраций (например: инициализация, отрисовка, обработка команд масштабирования, воспроизведение по таймлайну).
    *   Служит фундаментом для обеспечения полиморфизма, чтобы клиентское приложение могло единообразно управлять любым объектом, независимо от его типа.

2.  **Специфичные модули типов `Demo<Тип>.js`:**
    *   Для каждого конкретного типа Демо-объекта (зафиксированного в таблице `demotypes`) в папке `demoLib/` создается собственный изолированный модуль.
    *   *Примеры:* `DemoMap.js` (для интерактивных карт), `Demo3D.js` (для трехмерных артефактов), `DemoPlayer.js` (для управляемого видео).
    *   Каждый такой модуль реализует специфичную для своего типа логику, расширяя или переопределяя методы базового «абстрактного класса» из `DemoA.js`.

## 6. Конфигурация среды отладки (Инструкция для периода разработки)
При генерации конфигурационных файлов, строк подключения, скриптов инициализации и переменных окружения агент должен строго соблюдать следующие настройки по умолчанию:

*   **Адрес веб-проекта (Базовый URL):** Везде, где требуется указать адрес сервера, URL API или хост для фронтенда, по умолчанию вставлять реальный адрес проекта: `https://ai`.
*   **Версия СУБД:** В качестве целевой базы данных используется **MySQL-8.2**. При написании SQL-скриптов, миграций или использовании специфичных функций ориентироваться строго на синтаксис и возможности MySQL версии 8.2+.
*   **Параметры подключения (PHP-конфиг):** В корне проекта находится файл конфигурации подключения к БД ММЛ — `settings_MML.php`. При написании серверных скриптов транзита данных или развертывании среды ИИ должен ориентироваться на его структуру:
    ```php
    <?php
    // settings_MML.php
    // Конфигурационный файл подключения к БД ММЛ (LEMMA)
    return [
        'DB_HOST'     => 'MySQL-8.2',
        'DB_NAME'     => 'demotest',
        'DB_USER'     => 'root',
        'DB_PASSWORD' => '',
        'DB_CHARSET'  => 'utf8mb4',
        'WEB_URL'     => 'https://ai'
    ];
    ```
