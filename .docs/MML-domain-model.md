# Описание предметной области проекта ЛЕММА (ЛЕкционная МультиМедиа Аудитория)

## Соглашение о терминах
В этом и других текстовых документах проекта понятия предметной области выделяются **написанием с Прописной буквы**. Это помогает отличить их от использования тех же слов в бытовом контексте.

## 1. Общие понятия и цели проекта
*   **МультиМедиа Лекция (ММЛ / ММ-Лекция)** — новая форма электронных образовательных ресурсов. Развивает форму классических видеолекций и автономных презентаций (слайд-шоу с речевым сопровождением и синхронизированным аудиотаймингом). 
*   **Задача ММЛ** — наиболее полная и точная фиксация материала учебной лекции для последующего использования в качестве электронного средства обучения.

---

## 2. Подсистема хранения и переиспользования (База материалов)
Для удобного накопления, организации, поиска и повторного использования демонстрационных единиц вводятся следующие сущности:

*   **Демо (Demo)** — мультимедийная демонстрация любого типа (графика, видео, аудио и др.).
*   **Карточка (Card)** — базовая единица хранения демонстрационных материалов. Каждая Карточка сохраняет ровно одно Демо.
    *   *Атрибуты Карточки:* Название (Name), Заметки (Notes) с описанием учебного значения, само Демо. Атрибуты используются для фильтрации, сортировки и поиска.
*   **Папка (Folder)** — именованный набор Карточек для их группировки по темам, времени создания или другим параметрам.
    *   *Атрибуты Папки:* Название (Name), Заметки (Notes).
*   **Ярлык Карточки (Shortcut)** — сущность, позволяющая включать одну и ту же Карточку в несколько разных Папок без её дублирования.

---

## 3. Подсистема подготовки лекции (Сценарии)
*   **Сценарий (Scenario)** — упорядоченная последовательность демонстраций, аналогичная презентации, задающая план проведения лекции/доклада.
*   **Слайд (Slide)** — составная часть Сценария. 
    *   *Создание Слайда:* Основной (но не единственный) способ — конвертация Карточки в Слайд. При этом создается новый экземпляр сущности Слайд, куда **копируются** основные поля Карточки (Название, Демо, Заметки).
    *   *Атрибуты Слайда:* Название (Name), Демо (Demo), Заметки (Notes), жесткая связь со Сценарием, Порядковый номер в Сценарии.

---

## 4. Подсистема проведения лекции (Лекции)
*   **Лекция (Lecture)** — информационная единица и сущность БД, создаваемая в момент, когда лектор начинает читать лекцию на основе Сценария.
    *   *Инициализация:* Изначально копирует Название (Name), Заметки (Notes) и другие метаданные из исходного Сценария.
*   **Раздел (Section)** — составная часть Лекции, сущность БД. Создается автоматически, как только лектор представляет (демонстрирует) очередной Слайд Сценария. Раздел всегда связан с конкретной Лекцией.
    *   *Атрибуты Раздела:* Порядковый номер Раздела в Лекции, Видео (Video) лектора, записанное в этот момент.
    *   *Копирование данных:* При создании Раздела в него **копируются** поля из текущего Слайда (Название, Заметки, Демо).
*   *Интерфейс воспроизведения:* Готовая Лекция напоминает двухэкранную видеолекцию, где синхронно транслируются экран с лектором (Видео) и экран демонстрации (Раздел/Демо).

---

## 5. Перспективные требования (Динамические демонстрации)
В технологии ММ-лекций заложена идея управления динамическим контентом. Лектору (в процессе записи), а затем и зрителю (при просмотре) должны быть доступны инструменты управления демонстрацией прямо внутри Слайда/Раздела:
*   **Интерактивные карты:** Изменение масштаба, перемещение по карте, нанесение пометок «на лету».
*   **3D-объекты (Артефакты):** Вращение объекта, масштабирование, осмотр с разных сторон.
*   **Управление видеопотоком:** Воспроизведение видео Демо целиком, замедленный повтор ключевого фрагмента, фиксация конкретного кадра для обсуждения.
